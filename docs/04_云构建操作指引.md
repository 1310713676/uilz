# 云构建操作指引 v1.0

> 目的：**在没有 PC 的情况下，把代码变成可安装的 APK。**
> 手段：GitHub 仓库 + GitHub Actions + GameCI 的 Unity 构建镜像。
> 前提认知：云构建解决的是"编译打包"，**不解决"在编辑器里调试 UI/Prefab"**。第一次构建几乎必然失败，需要看日志迭代。

---

## 一、需要准备什么

| 项 | 要求 | 成本 |
|---|---|---|
| GitHub 账号 | 免费 | 0 |
| Unity 账号 | Personal（年收入 < 10 万美元） | 0 |
| Unity 版本 | **2021.3 LTS**（与逻辑层验证版本对齐） | 0 |
| GitHub Actions 额度 | 私有仓库 2000 分钟/月，公开仓库不限 | 0（单次构建约 15–30 分钟） |

**不需要**：Unity 订阅（Plus/Pro）、本地 Unity 安装、Android SDK。

> 注意：Unity Personal 版**不能去掉启动 Splash**，会显示 "Made with Unity" 约 3 秒。要移除必须升级 Plus/Pro。

## 二、两条路径

### 路径 A：有 PC（推荐，成功率高）

```
Unity Hub 建工程（2021.3.x + URP）
  → 拷入 src/Logic、src/Core，配 3 个 asmdef
  → 建 Battle 场景 + 挂 BattleSceneController
  → 本地 Play 跑通（这一步能省掉云端几轮试错）
  → git push 到 GitHub
  → GitHub Actions 自动出 APK
```

**为什么推荐**：本机能做的都做完了，`MatchBootstrap` 只做过编译验证。**本地 Play 一次能暴露几十个配置问题**，在云端靠日志猜是十倍的时间成本。

### 路径 B：零 PC（可行但需要试错）

关键事实：**Unity 工程的最小骨架是纯文本**。

```
ProjectSettings/ProjectVersion.txt   ← 一行版本号
Packages/manifest.json               ← 包列表
Assets/Scripts/...                   ← 我们的代码
Assets/Editor/BuildScript.cs         ← 用代码生成场景并打包
```

`ProjectSettings` 的其它 `.asset` 缺失时 Unity 会自动生成默认值。场景不用手写——用 **自定义构建方法**在构建前程序化创建。

代价：这条路**没有经过验证**，第一次跑大概率要改 2–3 轮。适合能读懂 Unity 日志的人。

## 三、仓库结构

```
DefenseCounter-unity/            （GitHub 仓库根）
├── .github/workflows/build.yml
├── Assets/
│   ├── Scripts/
│   │   ├── Logic/               ← src/Logic 全部
│   │   ├── Core/                ← src/Core 全部
│   │   ├── Logic.meta ...       ← Unity 自动生成，首次提交可以不带
│   ├── Editor/
│   │   └── BuildScript.cs       ← 自定义构建入口（路径 B 必需）
│   └── Scenes/                  ← 路径 A 才有
├── Packages/manifest.json
├── ProjectSettings/ProjectVersion.txt
└── .gitignore
```

**不要提交**：`Library/`、`Temp/`、`Logs/`、`obj/`、`Build/`。

## 六、GitHub Actions 配置

`.github/workflows/build.yml`：

```yaml
name: Build Android APK

on:
  push:
    branches: [ main ]
  workflow_dispatch:

jobs:
  build:
    name: Build
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          lfs: true

      - uses: actions/cache@v4
        with:
          path: Library
          key: Library-Android-${{ github.sha }}
          restore-keys: |
            Library-Android-

      - uses: game-ci/unity-builder@v4
        env:
          UNITY_LICENSE: ${{ secrets.UNITY_LICENSE }}
          UNITY_EMAIL: ${{ secrets.UNITY_EMAIL }}
          UNITY_PASSWORD: ${{ secrets.UNITY_PASSWORD }}
        with:
          targetPlatform: Android
          unityVersion: 2021.3.33f1
          # 路径 B 需要显式指定构建方法：
          # buildMethod: DefenseCounter.EditorTools.BuildScript.BuildAndroid

      - uses: actions/upload-artifact@v4
        with:
          name: DefenseCounter-Android
          path: build/Android
```

`Library` 缓存是必须的：冷启动首次导入要 15–25 分钟，缓存后 5–10 分钟。

## 七、License 配置（最易卡住的一步）

GameCI 需要 `.ulf` 许可证文件。获取方式：

1. 本地（或临时用的机器）执行 GameCI 的 `unity-request-activation-file`，得到一个 `.alf`
2. 打开 `license.unity3d.com/manual`，上传 `.alf`
3. 选择 **Unity Personal**，下载 `.ulf`
4. 把 `.ulf` 全文存为仓库 Secret：`UNITY_LICENSE`
5. 同时加 `UNITY_EMAIL`、`UNITY_PASSWORD`（激活时需要）

**常见失败**：`.ulf` 里含有换行，粘贴到 Secret 时被截断 → 构建报 "License not found"。解决：整个文件内容一次性粘贴，不要手改。

## 八、路径 B 的构建脚本

`Assets/Editor/BuildScript.cs`（程序化建场景 + 打包，无手写场景文件）：

```csharp
using System.Linq;
using UnityEditor;
using UnityEditor.SceneManagement;
using UnityEngine;
using UnityEngine.SceneManagement;

namespace DefenseCounter.EditorTools
{
    public static class BuildScript
    {
        public static void BuildAndroid()
        {
            // 1. 新建空场景并保存
            var scene = EditorSceneManager.NewScene(NewSceneSetup.EmptyScene, NewSceneMode.Single);
            var camGo = new GameObject("Main Camera");
            var cam = camGo.AddComponent<Camera>();
            cam.orthographic = true;
            cam.orthographicSize = 40f;
            camGo.transform.position = new Vector3(0f, 40f, 0f);
            camGo.transform.rotation = Quaternion.Euler(90f, 0f, 0f);

            var ctrl = new GameObject("BattleController");
            ctrl.AddComponent<BattleSceneController>();   // 需要该类已存在

            EditorSceneManager.SaveScene(scene, "Assets/Scenes/Battle.unity");
            EditorBuildSettings.scenes = new[] { new EditorBuildSettingsScene("Assets/Scenes/Battle.unity", true) };

            // 2. 打包
            var report = BuildPipeline.BuildPlayer(new BuildPlayerOptions
            {
                scenes = EditorBuildSettings.scenes.Select(s => s.path).ToArray(),
                locationPathName = "build/Android/DefenseCounter.apk",
                target = BuildTarget.Android,
                options = BuildOptions.None
            });

            if (report.summary.result != UnityEditor.Build.Reporting.BuildResult.Succeeded)
            {
                throw new System.Exception("Build failed: " + report.summary.result);
            }
        }
    }
}
```

**注意**：这个脚本引用 `BattleSceneController`，它目前还不存在——需要先写（Unity 侧 MonoBehaviour，无法在本机验证）。

## 8.5 一键生成配置资产（路径 B 必需）

**问题**：手机上没有 Inspector，无法手工创建 6 建筑 + 4 兵 + 2 技能 + 2 阵容 + 1 关卡 + 4 难度 + 1 数据库 = **20 个 ScriptableObject 资产**。

**解法**：`ConfigSeederEditor` 提供菜单项，用 `ReferenceDatabase` 的数据（已被 150 条断言验证过）反向生成资产。

```
菜单：DefenseCounter → Seed Data Assets
```

执行后会：

1. 创建 `Assets/Data/{Units,Buildings,Skills,Loadouts,Levels,AI}` 六个目录
2. 用 `ConfigSeeder.Apply(...)` 把每条 `Spec` 反向写成 `Config` 字段
3. 生成/复用 20 个 `.asset`
4. 全部塞进 `GameDatabase`
5. **自动跑一次 `ValidateAll()`**，有问题直接 `LogError`

关键性质：

| 性质 | 说明 |
|---|---|
| **幂等** | `GetOrCreate` 会复用已存在的资产，重复执行不会产生重复条目 |
| **可覆盖** | 每次执行会 `Clear()` 六个列表后重新填充，改过 `ReferenceDatabase` 再跑一次即可同步 |
| **自带校验** | 生成完立刻 `ValidateAll()`，数组长度不足 / 引用断链当场报错 |
| 生成顺序 | 兵种 → 建筑 → 技能 → 阵容 → 关卡 → 难度，符合引用依赖 |

**这一层无法在本机验证**（需要 `UnityEditor.dll`），所以刻意做得很薄：`ConfigSeederEditor` 只负责 `CreateAsset`，字段赋值全在能被本机编译验证的 `ConfigSeeder` 里。

如果生成后 `ValidateAll` 报错，先怀疑两处：

- `ReferenceDatabase` 的数组长度（必须是 3）
- 建筑 `id` 与阵容 `buildingIds` 不一致

## 九、预期会踩的坑（按概率排序）

| 现象 | 原因 | 处理 |
|---|---|---|
| `Library/` 未缓存，构建超时 | 首次导入全量资源 | 加 cache action，或接受首次 25 分钟 |
| License 报错 | Secrets 缺项或 `.ulf` 被截断 | 重新粘贴整份 `.ulf` |
| asmdef 找不到 `DefenseCounter.Logic` | asmdef 未提交或引用名不一致 | 检查 `name` 字段与 `references` |
| 场景为空 / 黑屏 | 没有 Scene 进 Build Settings | 用 `EditorBuildSettings.scenes` 显式设置 |
| `GameDatabase` 为空 | ScriptableObject 资产没建 | 用菜单 **DefenseCounter → Seed Data Assets** 一键生成（见第 8.5 节） |
| IL2CPP 编译失败 | 缺 `link.xml` 或泛型裁剪 | 加 `link.xml` 保留 Logic 命名空间 |
| APK 装不上 | minSdk / 架构不匹配 | PlayerSettings 设 `ARM64` + `minSdk 24` |

最后一条要专门说：**IL2CPP 的代码裁剪会删掉没有被显式引用的类型**。`Logic` 层大量使用反射？没有——但 `ScriptableObject` 子类和 `[SerializeField]` 字段会被保留，问题不大。保险起见加一个 `link.xml`：

```xml
<linker>
  <assembly fullname="DefenseCounter.Logic" preserve="all"/>
  <assembly fullname="DefenseCounter.Core" preserve="all"/>
</linker>
```

## 十、验证清单

构建成功后，按顺序确认：

- [ ] APK 能安装到手机
- [ ] 冷启动 < 3 秒
- [ ] 屏幕上有东西（不是纯黑）
- [ ] Gizmos / 占位方块能看见 AI 在造塔
- [ ] 5 分钟内基地血量有变化
- [ ] Logcat 无红色 Error

## 十一、诚实评估

| 环节 | 风险 |
|---|---|
| GitHub Actions + GameCI 本身的可用性 | 低，社区方案成熟 |
| License 配置 | 中，纯流程问题，卡住就查日志 |
| **项目自身的 Core 层能否跑起来** | **高** —— 只做过编译验证，运行时行为完全未知 |
| UI（目前不存在） | 必做，但现在没有任何界面代码 |

**所以云构建的第一步不是"出 APK"，而是"跑出一个能看到 Gizmos 的空场景"。**
先让 AI 在自己基地旁边造出一座塔，再谈 UI 和美术。
